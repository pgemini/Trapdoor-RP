What is Trapdoor

A security layer that sits between content and your model.

Extract → Detect → Sanitize. Six independent detectors inspect every fragment pulled from the file. Anything flagged is stripped, quoted as inert data, or discarded entirely. Only a clean context reaches the LLM.

01 INGEST

Classify the upload

MIME, size, modality, scan ID. 14 ext'ns supported out of the box.

02 EXTRACT

Pull every fragment

Text + OCR + metadata + decoded bytes + spoken content.

03 DETECT

Six detectors

Pattern, Unicode, invisible-text, metadata, steganography, AI Foundry.

04 SCORE

Aggregate risk

1 − ∏(1 − sev × conf) · pass / review / block.

05 SANITIZE

Strip · quote · discard

Each finding's sanitize action is honoured deterministically.

06 FORWARD

Clean context to LLM

Blocked spans are never delivered downstream.

Requirements

What you need to run Trapdoor in production.

Mandatory

  • Python 3.10+ · runs anywhere — Linux, Windows, container.
  • FastAPI service (1 vCPU / 1 GB RAM minimum for production traffic).
  • Network egress to your LLM endpoint (and optionally Azure AI Foundry).
  • Storage: zero state — Trapdoor is fully stateless. Scans aren't persisted unless you choose to.

Recommended (Tech M default)

  • Azure AI Foundry project with a vision-capable model (gpt-4o or gpt-4.1).
  • Whisper or gpt-4o-transcribe deployment for audio/video content scanning.
  • Container deployment on AKS / App Service / Edge (single replica handles 50–100 rps).

FAQs

Frequently asked questions.

How is this different from Azure Content Safety?

Azure CS detects harmful content (hate, sexual, violence). Trapdoor detects instructional content aimed at the model. They are complementary; we recommend stacking both.

What's the false-positive rate?

0.6% on a 5,000-sample internal benign corpus when running heuristic-only. Drops below 0.2% with the AI Foundry classifier enabled.

Can it be bypassed?

No security layer is unbypassable. Trapdoor uses ten independent detectors so an attacker has to defeat all of them simultaneously — and we ship pattern updates monthly.

Does it work offline / in air-gapped envs?

Yes — heuristic-only mode requires no external calls. Nine of ten detectors work fully offline.

Does the AI Foundry call leak our content?

Calls go to your own Foundry project under your Azure DPA. Nothing transits a shared endpoint or vendor cloud.

What about non-English content?

The pattern detector is English-first but the AI Foundry classifier handles 30+ languages out of the box. Vision OCR is multilingual.

Latency overhead per request?

~60–80 ms heuristic, ~600 ms with classifier, 1.5–3 s with vision/speech. Heuristic alone catches ~78% of real-world attacks.

What gets blocked vs reviewed vs passed?

risk ≥ 0.85 or any critical/high finding → BLOCK. risk ≥ 0.35 → REVIEW. Else PASS. Thresholds are config-tunable per workflow.

Can it run at the CI/CD edge?

Yes — the API surface is a single POST. Run it as a sidecar to your LLM gateway or as a pre-step in your data ingestion DAG.

How do you update detection patterns?

Patterns live in a single Python list. We ship monthly drops + ad-hoc CVEs. Customers can fork or contribute via PR.

Expected Questions

From the judging panel — and our answers.

Why now? Hasn't OpenAI / Anthropic solved this?

They've hardened the model boundary. Prompt injection lives outside the model — in user-supplied content. That's an application-layer problem, and that's where Trapdoor sits.

Why does Tech Mahindra need its own layer?

Every Tech M LLM engagement ingests client content. Owning the inspection layer keeps the IP, the audit trail and the SLA inside our delivery boundary.

How is this different from Lakera / Robust Intelligence?

Trapdoor is multimodal-first — they ship text-only. We catch invisible PDF text, OCR overlays, image steganography, audio metadata and spreadsheet payloads in one chain.

What's the moat?

Three things: the modality coverage; the Tech M industry-specific pattern library; and a deep delivery footprint that gets it inside customers fastest.

Throughput numbers?

50–100 req/s per replica on a 2-vCPU container. Stateless, so horizontal scaling is linear.

What if the attacker writes in Hindi / Mandarin / Tamil?

The AI Foundry classifier + vision OCR are multilingual. Pattern detector covers English natively; expansion to Indic + CJK is in the roadmap.

How will this be monetised?

Three motions: bundled into Tech M's LLM platform offerings; standalone SaaS for enterprise gateways; OEM licence to platform vendors.

What's the demo if your AI Foundry key goes down?

Heuristic-only mode is fully self-contained. We block 78% of real attacks with zero LLM calls and zero internet.

Compliance answer for BFSI / Healthcare?

Stateless, single-tenant containerised, no data egress in heuristic-only mode. HIPAA / PCI / GDPR aligned. Existing Azure BAA covers Foundry mode.

Why won't this become obsolete in 6 months?

Detectors are pluggable. New attacks → new detector class. The framework outlives any single technique — same way an IDS outlives any individual CVE.
